## 4. 학습 내용 → 실제 기능 매핑 [자체 검토]

| 학습 포인트 | Claude Code 기능 | 실습 방법 |
|---|---|---|
| 계획 수립 우선 | Plan mode | `Shift+Tab`으로 권한 모드 전환 → Plan mode에서 계획만 받고 승인 후 실행 |
| 컨텍스트 관리 | `/compact`, `/clear`, `/context` | 대화가 길어지면 `/compact`로 요약, 주제가 바뀌면 `/clear`로 초기화, `/context`로 사용량 확인 |
| 교차 검토 | 서브에이전트, 리뷰 명령 | 작업 종료 전 독립 서브에이전트에 검토만 맡기거나 `/code-review`(설치된 경우) 실행 |
| 프로젝트 규칙 저장 | `CLAUDE.md` | `/init`으로 초안 생성 → 빌드·테스트 명령, 코딩 규칙, 금지 사항 기재 → `/memory`로 수정 |
| 멀티 에이전트 분업 | 서브에이전트 | `/agents`로 생성, 정의 파일은 `.claude/agents/*.md` |
| 외부 도구 연결 | MCP | `claude mcp add ...`로 서버 등록, `/mcp`로 연결 상태 확인 |
| 위험 명령 차단 | 권한 설정, Hooks | `.claude/settings.json`의 `permissions.deny`에 차단 규칙 기재, `PreToolUse` 훅으로 실행 전 검사 |
| 자동 승인 범위 | 권한 모드, `permissions.allow` | 자주 쓰는 읽기 전용 명령만 allow에 등록, `/permissions`로 확인 |

### 권한 설정 예시 (`.claude/settings.json`)

```json
{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Bash(git status)",
      "Bash(git diff:*)"
    ],
    "deny": [
      "Bash(rm -rf:*)",
      "Bash(git push --force:*)",
      "Read(./.env)",
      "Read(./secrets/**)"
    ]
  }
}
```

- `deny`는 `allow`보다 우선 적용
- 비밀정보 파일(`.env` 등)은 읽기 자체를 차단하는 것을 권고

### CLAUDE.md 최소 구성 예시

```markdown
# 프로젝트 규칙
## 명령어
- 빌드: npm run build
- 테스트: npm test (변경 후 반드시 실행)
## 코드 규칙
- TypeScript strict 모드, any 사용 금지
## 금지 사항
- main 브랜치 직접 push 금지
- 마이그레이션 파일 수정 금지
```

## 5. 권장 학습 순서 (체크리스트)

- [ ] 1단계: 공식 과정 1~4 레슨 수강, Claude Code 설치 후 빈 저장소에서 기본 대화 실습
- [ ] 2단계: 실제 저장소에서 `/init` 실행, 생성된 CLAUDE.md 검토·보완
- [ ] 3단계: Plan mode로 기능 하나 계획 → 승인 → 실행 → 테스트까지 1회 완주
- [ ] 4단계: 긴 세션에서 `/compact`·`/clear` 시점 체험, `/context`로 사용량 비교
- [ ] 5단계: `settings.json`에 allow·deny 규칙 작성, 차단 동작 확인
- [ ] 6단계: MCP 서버 1개(예: GitHub) 연결, 서브에이전트로 교차 검토 실습

## 6. 유의 사항

- 강의 분량·레슨 수·한국어 지원 여부는 요약 자료 기준이며, 과정 페이지 원문과 대조하지 않음
- Claude Code는 업데이트가 잦아 명령어·단축키·설정 키가 변경될 수 있음
  - 공식 문서: https://code.claude.com/docs
- 자동 승인(allow) 범위를 넓게 잡으면 의도치 않은 파일 수정·명령 실행 위험이 커짐. 읽기 전용 명령부터 단계적으로 허용 권고
