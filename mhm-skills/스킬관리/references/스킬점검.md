# 스킬점검 모드

목적: 스킬이 늘수록 생기는 세 가지 문제 — 엉뚱한 스킬 호출(중복·충돌), 낡은 기준값, 판을 거듭하며 비대해진 본문 — 를 정기적으로 찾아낸다. 원본은 수정하지 않고 지적만 한다.

## 1. 입력 확보
- 1순위: 스킬 파일 원문(SKILL.md, references). 접근 가능하면 읽는다.
- 2순위: 스킬 목록(이름 + 설명)만 보이는 경우 설명 기준으로 평가하고, 본문 항목(간결성·실행가능성·검증표기)은 "[추정] 본문 미열람"으로 표시한다.
- 사용자가 특정 스킬만 지정하면 그것만 점검한다.

## 2. 평가 기준 (100점)
| 기준 | 배점 | 감점 포인트 |
|---|---|---|
| 호출 조건 명확성 | 20 | 트리거·"사용하지 않는 경우"가 없거나 모호 |
| 중복·충돌 | 20 | 다른 스킬과 트리거 문구가 겹치는데 경계 규칙이 없음(예: 같은 #태그) |
| 최신성 | 20 | 법령·공시규정·세율·양식 기준일이 오래되었거나 기준일 표기 없음 |
| 검증 표기 준수 | 15 | [확인]/[추정], [원문 대조]/[재계산], [미실행] 규칙 미반영 |
| 간결성 | 15 | 판(18판·19판…) 변경 이력이 본문에 누적, 같은 내용 반복, SKILL.md 500줄 초과 |
| 실행가능성 | 10 | 산출물 양식·파일명·종료 조건이 불명확 |

등급: A 90↑ / B 80~89 / C 70~79 / D 60~69 / F 60 미만. 점수는 산식 병기(예: 20+15+12+…=82).

## 3. 우선 점검할 중복군
아래는 이름·설명만 봐도 경계가 겹치기 쉬운 묶음이다. 목록에 있으면 반드시 묶어서 본다.
- 한글 문서: hwpx / 한글-kordoc / 한글-gongmunseo
- PPT: mhm-ppt-skill / mhm-edu-ppt / 외부ppt-디자인 / pptx
- 문서: docs / docx
- 회고·인계: 검토보고(#회고) / handoff / 스킬관리(#세션회고)
- 검토 계열: 검토보고 / 기획착수 / 아이디어검증 / 사고틀 / grilling

새로 발견한 중복군이 있으면 추가한다.

## 4. 산출물
1. **요약**: 점검 대상 수, 평균 점수, 심각 지적 건수.
2. **점수표**: 스킬 | 6개 기준 점수 | 합계(산식) | 등급.
3. **지적표(심각도순)**
   | 번호 | 심각도 | 스킬 | 지적 | 근거(설명·본문 인용) | 권고 조치 |
   |---|---|---|---|---|---|
   - 심각도: 상(오호출·오판정 유발) / 중(유지보수 부담) / 하(표기·형식)
   - 권고 조치는 수정 / 통합 / 폐지 / 경계 문구 추가 중 하나로.
4. **통합·폐지 제안**: 있으면 A(권고)/B(보수)/C(현상유지) 비교.
5. 승인 요청 후 멈춤. 승인 항목만 `_v2` 수정안 작성(공통 규칙 2-2).

## 5. 한계 표기
- 본문을 읽지 못한 스킬은 점수에 "[추정]"을 붙인다.
- 실제 호출 정확도는 이 모드로 측정할 수 없다. 필요하면 skill-creator의 트리거 테스트를 권고한다.
