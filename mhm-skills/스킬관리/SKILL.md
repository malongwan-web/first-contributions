# 스킬관리

사용자(MH머트리얼즈 기획관리팀)의 Claude 프로필과 사내 스킬이 대화를 거듭할수록 정확해지도록 유지보수한다. 프로필·스킬은 매 대화의 판단 기준이 되므로, 잘못된 규칙 하나가 이후 모든 산출물을 오염시킨다. 그래서 이 스킬은 **후보를 제시하는 데서 멈추고, 반영은 사용자 승인 뒤에만** 한다.

## 1. 모드 판별

요청을 보고 아래 중 하나만 실행한다. 세 모드를 한꺼번에 돌리지 않는다 — 점검·최신성은 시간과 검색 비용이 크고, 사용자는 대개 그중 하나만 원한다.

| 요청 신호 | 모드 | 읽을 파일 |
|---|---|---|
| #세션회고, "회고", "이번 대화 반영", "오늘 정한 규칙" | 세션회고 | `references/세션회고.md` |
| #스킬점검, "스킬 점검", "스킬 정리", "겹치는 스킬" | 스킬점검 | `references/스킬점검.md` |
| #최신성점검, "개정 반영됐나", "기준값 최신인가" | 최신성점검 | `references/최신성점검.md` |
| "/스킬관리"만 입력 등 불분명 | 1회 질문 | 답이 없으면 세션회고(가장 가벼움) |

- "#회고"만 단독으로 오고 안건·결재 맥락이면 검토보고 소관이므로 이 스킬을 쓰지 않는다. 대화 자체의 규칙 정리를 원하는 것이 분명할 때만 세션회고로 본다.
- 스킬점검·최신성점검은 사용자가 명시적으로 요청했을 때만 실행한다.

해당 모드의 references 파일을 읽고 그 절차를 따른다. 아래 공통 규칙은 모든 모드에 적용된다.

## 2. 공통 규칙

### 2-1. 승인 게이트
- 어떤 모드든 첫 산출물은 **후보표 또는 지적표**다. 그 시점에 멈추고 승인을 기다린다.
- 사용자가 번호로 승인한 항목("1, 3 반영")만 처리한다. 충돌 항목은 묶음 승인("전부 반영")에서 빼고 개별 확인한다.

### 2-2. 반영처 지정
| 반영처 | 대상 | 처리 방식 |
|---|---|---|
| Claude 프로필 | 전 업무 공통 원칙 | Claude는 프로필을 직접 수정할 수 없다. 프로필 해당 절(1.역할~6.공동문서)과 붙여넣기용 문안을 제시 |
| 개별 스킬 | 특정 업무에만 해당 | 원본은 두고 `_v2` 수정안(변경 부분 + 위치) 작성. 스킬 파일 접근이 없으면 문안만 제시 |
| 공시판단 스킬 | 공시 기준값·공시 판정 | 프로필 원칙상 Claude 작업으로만 처리. 노션 등 공동 문서에는 반영하지 않음 |
| handoff 이관 | 미결 사항 | 규칙으로 만들지 않고 인계 목록으로 넘김 |

- 노션 공동 문서는 현재 판(v1)의 반영처가 아니다. 필요하면 "노션 반영 후보"로 표시만 한다.

### 2-3. 표기
- 사실은 [확인], 추론은 [추정]. 사용자가 직접 말한 것만 [확인]이다.
- 실제로 수정·생성한 것만 "완료", 하지 못한 것은 [미실행].
- 공시 전 정보(미공개 M&A·실적·계약)가 대화에 있었으면 산출물 첫 줄에 "공시 전 정보" 표시. 단, 후보 문구 자체에는 회사명·금액·상대방을 지운 일반 규칙만 쓴다.
